## 2024-11-01 - SSRF Bypass via IPv4-Mapped IPv6 Addresses
**Vulnerability:** The SSRF protection logic (`is_blocked_ip`) was bypassing loopback and private IP checks when given IPv4-mapped IPv6 addresses (e.g. `::ffff:127.0.0.1`), allowing requests to internal network resources. Furthermore, `validate_url` retained URL brackets (e.g., `[::ffff:127.0.0.1]`), causing DNS resolution failure prior to the IP check instead of properly verifying the raw IP.
**Learning:** Rust's standard library `IpAddr` operations do not implicitly unmap `IpAddr::V6` holding IPv4-mapped addresses. An IP like `::ffff:127.0.0.1` is strictly treated as an IPv6 address, so IPv4 subnet matching (like checking for 127.0.0.0/8) fails silently, opening an SSRF bypass.
**Prevention:** Always manually unmap IPv4-mapped IPv6 addresses using `ipv6.to_ipv4_mapped()` before applying range checks. Additionally, always trim bracket characters from URLs containing raw IPv6 hosts before performing socket resolution or IP validation.
