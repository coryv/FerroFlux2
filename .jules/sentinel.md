## 2025-02-14 - URL Validation for Server-Side Request Forgery (SSRF)
**Vulnerability:** Execution action nodes accept dynamic URL paths derived from potentially untrusted inputs, allowing an attacker to execute HTTP requests against arbitrary hosts, including local or internal loopback IP addresses (SSRF), if validation is omitted.
**Learning:** Raw string concatenations or templating into full URLs, especially when passed directly to an unconfigured HTTP client like `reqwest::Client`, poses a critical risk if it isn't strictly validated via a secure network validator to block access to private/reserved IP ranges. The core engine was exposed because it didn't use the existing `ferroflux_security::network::validate_url` guard before firing off action implementation HTTP requests.
**Prevention:** Always parse and explicitly validate URLs against a strict whitelist or filter for private IP ranges (e.g., using `ferroflux_security::network::validate_url`) before issuing outbound server-side HTTP requests.
