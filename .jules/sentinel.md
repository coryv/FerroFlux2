## 2025-02-27 - Insecure Permissions on Master Key Generation
**Vulnerability:** The `ferroflux.key` master encryption key was being generated and written to disk using `std::fs::write` with default system permissions (often `0644`), making it potentially readable by other local users on the system.
**Learning:** Even when auto-generating files only in "dev mode" or fallback scenarios, sensitive material (like encryption keys or API tokens) must always be protected at the file-system level immediately upon creation to prevent local privilege escalation or information disclosure. The `ferroflux-security` crate handles encryption, API key management, signing, and network validation. It follows a convention of using restricted permissions (`0o600`) for sensitive files like `api.key` and `ferroflux.key`.
**Prevention:** When creating files containing sensitive secrets on Unix platforms, use `std::fs::OpenOptions` with `.mode(0o600)` (via `std::os::unix::fs::OpenOptionsExt`) rather than the convenience `fs::write` function.
