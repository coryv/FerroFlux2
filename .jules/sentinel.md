## 2024-05-24 - SSRF Bypass via IPv4-Mapped IPv6
**Vulnerability:** The SSRF protection mechanism `is_blocked_ip` in `ferroflux-security` was susceptible to bypasses using IPv4-mapped IPv6 addresses (e.g., `::ffff:127.0.0.1`). Standard IPv4 checks failed to identify the loopback IP because it was wrapped in an IPv6 format. Furthermore, `check_ssrf` in `ferroflux-tools` used insecure string matching to validate hosts.
**Learning:** When validating IP addresses for SSRF protection, developers must explicitly unmap IPv4-mapped IPv6 addresses to IPv4 before applying range checks, as underlying OS network stacks will often treat them as standard IPv4 addresses. Naive string matching on URLs for SSRF protection is inherently flawed because it does not account for DNS resolution.
**Prevention:** Use `IpAddr::to_ipv4_mapped()` in Rust to normalize IPs before checking if they fall within blocked ranges. Always resolve URLs to IPs for validation rather than relying on host string matching.
