## 2026-10-19 - Prevent SSRF via IPv4-mapped IPv6 Addresses
**Vulnerability:** The SSRF protection in `is_blocked_ip` (crates/ferroflux-security/src/network.rs) checked IPv4 addresses against private/loopback ranges, but failed to detect IPv4-mapped IPv6 addresses (e.g., `::ffff:127.0.0.1`). Furthermore, standard URL parsing retains brackets around IPv6 addresses which causes `to_socket_addrs()` to fail, effectively bypassing host resolution entirely for bracketed IPv6/IPv4-mapped addresses.
**Learning:** IPv6 parsing and resolution can have subtle edge cases. `std::net::Ipv6Addr::to_ipv4_mapped()` must be explicitly checked, and IPv6 brackets from URL hosts must be trimmed before socket resolution, to ensure IPv4-mapped IPv6 addresses are correctly evaluated against the IPv4 blocklist.
**Prevention:** Always strip brackets from IPv6 host strings before resolving them, and always unmap `IpAddr::V6` using `to_ipv4_mapped` before applying address-specific blocklist logic to avoid bypasses via mapping encodings.
